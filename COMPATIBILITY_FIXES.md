# Minecraft 26.2 Create compatibility fixes

This source tree includes compatibility fixes for the Minecraft 26.2 NeoForge port:

1. Restored Create's official Java namespace from `com.zurrtum.create` to `com.simibubi.create` throughout main/client Java sources and resource configuration. This allows mods compiled against Create's normal API/package names (including Sophisticated Core) to resolve Create classes such as `com.simibubi.create.content.contraptions.AbstractContraptionEntity`.
2. Restored `CuboidModelMixin` for Create's `neoforge:obj` water-wheel models, and changed `UnbakedModelParser` to delegate unknown custom loaders to the previously installed parser. This preserves Create OBJ models without forcing Sophisticated Backpacks or Sophisticated Storage models through Minecraft's ordinary cuboid parser.
3. Restored kinetic stress initialization. The early registry service provider is now present, and `AllConfigs.register()` explicitly calls the idempotent `AllBlocks.init()` before building the stress config. Water wheels, the Creative Motor, kinetic sources, and consuming machines now receive their configured stress capacities and impacts.
4. Added an optional Pollution of the Realms 26.2 smoke-only configuration. It disables carbon, sulfur, and dust emissions globally, preserves Advanced Chimneys visual smoke, and updates Create's Crushing Wheel Controller activity tag to the 26.2 root `ProcessingTime` field.
5. Replaced the obsolete `LivingEntity.baseTick` breathing call wrappers with a stable tail injection for Minecraft 26.2. Diving helmets and backtanks retain underwater and lava breathing without crashing mod loading when the old vanilla invocation targets are absent. The server world is obtained through the 26.2 `level()` API rather than the removed `ServerPlayer.serverLevel()` method.
6. Replaced `EntityFluidInteractionMixin`'s obsolete local-variable capture with a stable tail injection. Create now detects custom fluids by scanning the entity bounding box after vanilla updates fluid contact, avoiding the removed `MutableBlockPos.getY()` bytecode target while preserving custom-fluid splash handling.
7. Disabled the old `RegistryDataLoaderMixin` on NeoForge. Minecraft 26.2 already receives `create:potato_projectile/type` through `DataPackRegistryEvent.NewRegistry`; enabling both paths registered the same datapack registry twice and prevented every world from loading.
8. Added identity-map fallbacks to Flywheel's visualizer registry. If Minecraft 26.2 loads `BlockEntityType` or `EntityType` before their client extension mixins are available, Create can still register and retrieve animated visualizers without an unsafe `ClassCastException`.
9. Updated all remaining build exclusions, verification paths, and injected-interface paths from `com.zurrtum.create` to `com.simibubi.create`.

Build note: source validation confirmed no `com.zurrtum.create` references remain. A Gradle compile could not be run in the ChatGPT runtime because the Gradle 9.4.1 wrapper distribution is not cached and outbound downloads are unavailable.
